# Decisions

Each decision with its status, the evidence and the alternatives considered.

## D0. Repository method: release tarball + patches + overlay (as the sibling ports)

**Status:** approved by the user (2026-10-08, plan).

The signed PHP release tarball pinned in `upstream.conf` (SHA-256 and the release manager's
GPG key in `keys/`), `patches/` applied in `patches/series` order, `overlay/` (add-only),
`staging/` generated by `tools/prepare.sh`, remote work through `tools/vms.sh`.

## D1. PHP version: 8.5 (latest), with 8.4 or 8.3 as fallbacks

**Status:** approved by the user (2026-10-08).

PHP 8.5.11 (24 Sep 2026), signed by Volker Dusch (`49D9AF6BC72A80D6691719C8AA23F5BE9C7097D4`,
from php.net's keyring). phpBB 3.3.19's `docs/INSTALL.html` lists PHP 7.2 "up to and
including PHP 8.3"; if phpBB fails on 8.5 in acceptance, the same port is re-pinned to 8.4 or
8.3 (the patches should mostly carry over). 8.5 adds two always-built extensions, `lexbor`
(bundled HTML/URL parser) and `uri`, and builds opcache in.

## D2. Compiler: clang (LP64) on x86-64

**Status:** approved by the user (2026-10-08, plan); x86-64 only for the first kit.

PHP's 64-bit build assumes `size_t` and pointers have the same width and uses GCC builtins
and `__atomic`; it needs C99 (C11 features optional). clang on x86-64 is LP64 with all of
these (vms-mariadb D4). VSI C on x86-64 is ILP32 with a 32-bit `size_t`: PHP would be a
32-bit build (32-bit integers, 2 GB limits) and lose the builtins. clang also allows the
HYBRID Zend VM (computed goto). Reused from vms-mariadb: `__GNUC__` defined in the clang
flags, the forced-include header for the C RTL's 32-bit `long` interfaces (D12), the
`LIB$INITIALIZE` feature logicals (D6).

Alternatives: VSI C (32-bit PHP, as the existing third-party kits; shares the vms-zlib,
vms-pcre2 and SSL3 `_SHR32` ABI, and would cover IA64) - rejected for x86-64; it stays the
route if IA64 is wanted later.

## D3. Extensions: static, the phpBB set

**Status:** approved by the user (2026-10-08, plan).

Built in (no `dl()`): the always-on set (Core, date, hash, json, lexbor, pcre, random,
Reflection, SPL, standard, uri, opcache) plus ctype, dom, filter, libxml, mbstring
(`--disable-mbregex`: no oniguruma), mysqli + mysqlnd, openssl, session, SimpleXML,
tokenizer, xml, xmlreader, xmlwriter, zlib. phpBB 3.3's hard requirements are json and
mbstring; its bundled libraries add dom and filter (s9e/TextFormatter), mysqli for the
board's database, openssl for SMTP over TLS. Not built: pdo, phar, gd (no image CAPTCHA or
thumbnails at first: user, 2026-10-08), intl, iconv, curl, sockets, posix, pcntl.

## D4. Dependencies: clang builds of the family's libraries

**Status:** approved by the user (2026-10-08, plan).

zlib: a clang (LP64) variant in vms-zlib (as vms-pcre2's for vms-mariadb D11); PCRE2:
vms-pcre2's clang tree (not PHP's bundled copy; JIT off); libxml2: a new sibling repository,
vms-libxml2; OpenSSL: VSI SSL3's 64-bit-pointer images with an audit of the `long`-typed
calls ext/openssl makes (vms-mariadb D9), our own OpenSSL build as the fallback.

## D5. Process model: no fork

**Status:** approved by the user (2026-10-08, plan).

The CGI SAPI runs as a FastCGI server (`-b`, `PHP_FCGI_CHILDREN=0`), one process per pool
member, exactly as vms-lighttpd's `PHP_POOL.COM` runs PHP today. `proc_open`, `pcntl` and
`mail()` are unsupported in the first kit; phpBB sends mail over SMTP.

## D6. Naming

**Status:** approved by the user (2026-10-08, plan).

PCSI product PHP (producer ISSINOHO), logical name `VMSPHP$ROOT`, images
`[BIN]PHP.EXE` and `[BIN]PHP_CGI.EXE`, settings `[ETC]PHP.INI`, `VMSPHP$STARTUP.COM`.
vms-lighttpd's pool takes the PHP root logical as a setting (`vmslighttpd_php_root`).
